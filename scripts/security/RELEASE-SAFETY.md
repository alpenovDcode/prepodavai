# Безопасное обновление после исправлений доступа 17.09.2026

Обычный запуск deploy.sh (для LMS — scripts/deploy.sh) теперь **только проверяет** состояние. Он не делает git pull/reset, не запускает сборки, миграции, Compose up/down, prune или перезапуск инфраструктуры. Push в основной Git больше не должен автоматически запускать production-команды: workflow LMS переведён в ручной режим и выполняет только офлайн-тесты инструмента релиза.

## Область действия

LMS: обновление приложения Next.js. Преподавай: обновление только Nest backend/API. Фронтенд Преподавай, worker, Telegram-бот и прочие компоненты требуют отдельного плана релиза; они не обновляются этим скриптом. Сборщик заданий не затрагивается.

Выкладка не зависит от предположений blue/green: текущий контейнер определяется по нужному блоку nginx. Другие блоки upstream сохраняются. Новое приложение наследует существующие runtime-параметры, сеть и тома, не получает публичных портов и запускается явной командой node, без исторического entrypoint с миграциями в CMD.

## Порядок следующего обновления

1. Проверить изменения команды и перенести их в Git отдельно. Не выполнять force reset. Скрипт --check выводит список незакоммиченных tracked-файлов; --apply откажется при таких изменениях (кроме управляемого runtime upstream.conf). Не добавлять в Git .env, бэкапы, экспорт учеников и загруженные файлы.
2. Собрать нужный Linux-образ из проверенного коммита с label `org.opencontainers.image.revision=<полный SHA коммита>`. Для LMS сохранить действующие публичные build-параметры NEXT_PUBLIC_*. Для Преподавай использовать backend Dockerfile и его обычный контекст. Сборка не входит в deploy.sh: сначала отдельный проверенный артефакт, затем выкладка. Label нужен для привязки к ревизии, но сам по себе не заменяет проверку происхождения образа.
3. `python3 -m unittest discover -s scripts/security -p 'test_*.py' -v` — офлайн-тесты процедуры.
4. `bash scripts/deploy.sh --check` (LMS) или `bash deploy.sh --check` (Преподавай) — чтение состояния без выкладки.
5. После явного согласования использовать тот же скрипт с `--apply --image <локальный тег/ID> --revision <полный SHA текущего HEAD>`. Будет закреплён неизменяемый image ID. Скрипт требует равенства схемы Prisma текущего и нового образов, проверяет привязку к коммиту и security-baseline, затем запускает 8 регрессионных проверок на изолированной временной PostgreSQL. Production-окружение тестам не передаётся; сеть internal, порты наружу отсутствуют, временная БД в tmpfs удаляется после тестов.
6. Только после успешных проверок создаётся новый контейнер, проверяется здоровье, сохраняется резерв, nginx переключается и проверяется HTTPS. Старый контейнер останавливается, но не удаляется; образ сохраняется. При ошибке выполняется возврат upstream к прежнему приложению. Не выполнять image/system prune до отдельного решения о сроках хранения.

Изменение схемы БД блокирует этот путь: миграции требуют отдельного плана и согласования. Если меняются защищённые исходники, обновление security manifest разрешено только вместе с проверкой логики и регрессионных тестов, не ради обхода проверки.

## Резерв и ограничения

Новые релизы сохраняют `/root/security-release-history/<project>-<UTC>/state.json`, прежний upstream и параметры контейнера. `container-inspect.json` содержит секреты; каталог root-only, его нельзя публиковать, копировать в Git или выводить в чат. Это не бэкап БД.

Откат завершённого релиза делается по сохранённым точным контейнерам/образам и upstream; перед запуском проверять CMD и Entrypoint, чтобы не запустить миграции. Исторический резерв первого security-релиза лежит в `/root/codex-security-20260917/` и имеет отдельный rollback-security-release.py. Старые docker-compose и entrypoint в проекте не являются новым безопасным путём: ручной compose up может по-прежнему запускать прежние команды.

Проверки доступа используют синтетические работы и не проверяют все бизнес-функции. Старые штатные unit-тесты проекта имеют независимые от security-патчей падения. Известный дефект выбора материала в учительском интерфейсе Преподавай — отдельная незакрытая задача.
