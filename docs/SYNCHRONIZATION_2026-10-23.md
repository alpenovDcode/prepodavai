## Релиз

Контейнеры собираются из зафиксированной ревизии с `org.opencontainers.image.revision`. Для экономии диска и сохранения проверенных системных библиотек backend/worker/bot используют уже проверенные runtime-образы как базу; зависимости устанавливаются заново по lock-файлам, Prisma и весь dist пересобираются из этой ревизии. Frontend собирается штатным Dockerfile с текущими публичными build-параметрами. Dockerfile релиза, журналы и хеши сохраняются в закрытом каталоге резервных копий.

До переключения обязательны резерв БД, Redis, Git и runtime-конфигурации, проверка восстановимости БД и изолированные проверки доступа. Затем кандидаты API/frontend проверяются, nginx переключается с откатом при ошибке. Worker и Telegram-бот заменяются последовательно при пустых активных очередях; одновременно два экземпляра бота не запускаются. PostgreSQL и Redis не перезапускаются. Env и тома сохраняются.

Результат фактической выкладки фиксируется отдельно в закрытом отчёте `/root/security-prepodavai-sync-oct23/REPORT.md` и его локальной копии `/Users/proryv_jarvix/security-backups/prepodavai-sync-oct23/REPORT.md`; этот документ описывает подготовленную процедуру, а не подтверждает её завершение.

`nginx/conf.d/upstream.conf` — управляемое runtime-состояние. Секреты `.env*`, `redis/security.conf`, резервные копии и загруженные пользовательские файлы в Git не добавляются.
